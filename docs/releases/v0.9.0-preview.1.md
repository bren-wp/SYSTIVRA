# SYSTIVRA v0.9.0-preview.1 — BRENDIGO Android package & stable dependencies

**Developer preview — new Android application identity, not an update to the old package.**

## Canonical application ID

The Android `applicationId` and `namespace` are now **`com.brendigo.systivra`**. All 24 Kotlin files, instrumentation and unit tests, package directories, GitHub capture scripts and Play metadata were migrated to that exact identifier. A Python pre-release validator blocks inconsistent builds.

**Important:** Android and Google Play regard this as a separate app. Existing installs under earlier IDs will not update to the new one, and locally stored history cannot transfer automatically due to sandbox isolation.

## Dependencies and privacy

- Gradle upgraded to **9.9.1** to include November 2026 security patches.
- kotlinx.coroutines-android upgraded to **1.11.0**, latest verified stable.
- Latest stable AGP 9.4.0, Kotlin 2.4.21, Compose BOM 2026.09.00, Activity 1.13.0, Core KTX 1.19.1, Lifecycle 2.11.0, SplashScreen 1.2.0.
- Google Play minimum target SDK API 36: the build uses targetSdk 36, compileSdk 37 and minSdk 24.
- The core app requests no INTERNET permission. Optional Usage Access remains user-controlled and is disclosed before opening Android settings.

## Deliverables

- `SYSTIVRA-v0.9.0-preview.1-unsigned.aab` — unsigned bundle, **not suitable for Play upload** until independently signed.
- `SYSTIVRA-v0.9.0-preview.1-source.zip` — tagged complete source.
- `SYSTIVRA-v0.9.0-preview.1-play-artwork.zip` — current brand graphic assets.
- `SHA256SUMS.txt` — sha256 of included release packages.

## QA & screenshots

Kotlin unit tests, Gradle lint, instrumentation-test compilation and APK/AAB bundling are required in release CI. Emulator screenshot verification is a separate step requiring real in-app images with no System UI/Quickstep ANRs. **No pixel-perfect 1:1 certification, universal crash-free guarantee or Google Play policy acceptance is claimed.** Existing marketing concepts are NOT actual app screenshots.

The store listing must use the exact new package ID and a publicly accessible HTTPS privacy policy. Production signing must be performed using the authorized developer upload key, never a key committed to GitHub.
