# SYSTIVRA v0.12.0-preview.10 — Export Integrity and Recording Recovery

**Android developer preview.** Not a Play Store production-signed bundle and not 37/37 pixel-perfect certified.

## Functional correctness

- **CSV, JSON and PDF export integrity:** previously the document picker callback could use the latest recording or selected session, which might have changed while Android's system picker was open. Preview 10 fixes the user-data race: on the actual export-button press, capture a detached copy of all samples and nine internal readings arrays. The callback consumes that exact pending request only once, irrespective of later recordings, filter changes or session switches. A canceled picker consumes the pending request and writes nothing. After process recreation, a lost request fails closed with a retry message; no other session is exported silently.
- **Offline SQLite crash recovery:** the Activity's storage actor now recovers unfinished sessions from any previous app/process interruption before loading history or accepting new recording actions. Genuine sample data remain available and session end time reflects the actual last recorded sample (never before start); sessions with zero measurements are removed. No sample is fabricated, no schema migration or new permissions are required. Existing ongoing sessions are not touched by this method while the Activity is recording.
- **Focused Performance Lab:** removed the inert development-only card advertising unsupported GPU/memory/storage benchmarks. Only the genuinely bounded, cancelable two-second CPU workload is shown, with thermal protection. Diagnostic Results now reports microphone/camera assessment as unavailable because SYSTIVRA has not requested that access; no fake pass is displayed.
- **UI reference preservation:** no edits to the 37 original SVG sources, app bottom-tab safe inset, colors, reference heading geometry or captured-artwork source. The modifications focus on real app reliability, data integrity, accurate copy and reduced dead control clutter.

## Regression and security checks

- New JVM tests verify that a pending export captures one immutable sample set even after active session and source-list mutation, that nested readouts cannot change, and that requests are consumed only once or fail closed.
- New Android SQLite instrumented tests simulate process death between the first sample and a Stop action, preserve the reading and its real timestamp, remove genuinely empty session records and check repeated recovery.
- Existing whole-application Compose emulator, Android lint and JVM suite, 38 native route screenshots vs 36 original reference SVG images, measured luminance/contrast, four responsive viewports (including 130% font), real Splash cold-start footage, static audit, file checksums and immutable exact HEAD-tag release checks remain mandatory.
