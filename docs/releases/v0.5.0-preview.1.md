# SYSTIVRA v0.5.0-preview.1 — Recording Library & Diagnostics

**Preview build for Android developers and testers. Not a Google Play production release.**

## Implemented improvements

- **Recording Library:** separate recording sessions, dates, sample counts, per-session analysis, and per-session CSV export.
- **Independent delete:** remove a selected session only after confirmation, leaving other sessions intact.
- **Lossless SQLite migration:** v1 saved samples are upgraded into a legacy session by the schema v2 migration. Database creation/reopen, migration and deletion are tested.
- **Bounded history:** the 900 most recent device metric samples are retained globally. Foreground-only, explicitly user-initiated recording; backup is disabled.
- **Vibration diagnostics:** a short optional vibration pulse with manually confirmed Pass/Fail status, shown in Diagnostic Results. The API uses only the normal VIBRATE permission.
- **Fixed emulator smoke test:** current Dashboard semantics and lazy-list scroll behavior are used instead of old UI labels and off-screen clicking.
- **Modern SYSTIVRA identity:** dark theme, blue/purple gradient, native Compose icons; English user interface, no account or onboarding.
- **CI:** Android compile, local JUnit and instrumented-test compilation before preview release. Emulator screenshot QA remains separate.

## Release assets

- SYSTIVRA-v0.5.0-preview.1-debug.apk — debug-signed APK for testing only.

GitHub also provides native source ZIP/TAR archives.

## Known limitations & visual acceptance

The 37 original design references are **not certified 1:1** to actual Android screenshots. The Recording Library is a new screen without its own approved visual baseline. The screenshot QA workflow and 1:1 comparison tooling exist, but real emulator images and diffs still need review and on-device correction. Marking the screens as pixel-perfect would be inaccurate at this stage.

Restricted GPU and CPU temperature metrics, other-app FPS, cross-app overlays, microphone/camera/speaker tests, expanded benchmarks, accessibility/device matrix and full security/dead-code audits are not fully completed. Unsupported readings are never fabricated.

Signing a Play-ready AAB requires the user's authorized private upload keystore, which is not stored in the repository.
