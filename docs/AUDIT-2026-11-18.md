# SYSTIVRA — Android security, dead-code and 37-screen design audit

**Date:** 2026-11-18  
**Baseline:** v0.12.0-preview.2; audit changes on PR #34.  
**Status:** Source-level audit findings addressed in PR; runtime validation of this PR must complete. **Not a full external penetration test or 1:1 certification.**

## Executive findings

| Priority | Finding / effect | Mitigation | Status |
|---|---|---|---|
| Medium | `MainActivity` used an unlimited asynchronous work channel. A blocked SQLite consumer could accumulate complete `DeviceSnapshot` objects and trigger excess heap pressure | Keep FIFO control actions, but limit queued sample payloads to 32 with a thread-safe CAS limiter; report dropped samples; test saturation and concurrency | Patched; regression tests added |
| Medium | On Android 12+ some device manufacturers permit device-to-device app data migration despite `allowBackup=false` | Explicit `dataExtractionRules` excluding the app-private root from both cloud backup and device transfer, retaining legacy backup disable flags | Patched; Android build must validate |
| Low/Medium | Export, benchmark and storage error displays concatenated `localizedMessage` with OS/SQLite provider exception details | Generic user-actionable errors without file paths, raw exceptions or framework internals | Patched |
| Defense in depth | Cleartext-traffic policy was unspecified | Explicit `usesCleartextTraffic=false`; the app already has no INTERNET permission | Patched |
| Open | SQLite data at rest relies on Android's app-private sandbox instead of a separately managed encrypted database | Keep no backup/device transfer and avoid secret/device identifiers; consider at-rest encryption with secure migration plan for higher-threat deployments | Requires threat model / migration QA |
| Open | Automated SAST regex scan cannot identify all Kotlin/Android logic vulnerabilities or transitive CVEs | Android Lint + JVM and emulator suites + pinned dependency review, new static CI scan; obtain SBOM/vulnerability advisory scan and external review before claiming full security acceptance | Not externally certified |
| Open | Unsigned release AAB and debug APK cannot constitute a store-production signed release | Sign future production AAB with user-controlled Play upload key and verify Play Console | Production blocker |

## Security surfaces reviewed

1. **Permissions / IPC / exported components:** AndroidManifest declares `ACCESS_NETWORK_STATE`, `VIBRATE` and optional `PACKAGE_USAGE_STATS`; no `INTERNET`, camera, microphone or broad storage permission. Only `.MainActivity` intentionally exported as a launcher. `qa_route` is considered only in debuggable builds. No custom Android provider, exported service or WebView bridge.
2. **SQLite and lifecycle:** private `SQLiteOpenHelper`, bounded global retention of 900 samples, parameterized selection/deletion, data writes through a single serialized actor, explicit user-initiated recording and deletion, database close on Activity lifecycle termination. Backlog is now limited to 32 full `DeviceSnapshot` objects pending I/O.
3. **Exports and privacy:** Storage Access Framework `CreateDocument` for CSV/JSON/PDF; Android Sharesheet opens only after a user tap; CSV formula injection prefix handling is present. Session export may reveal activity/thermal timestamps to a *user-chosen* destination, so consent remains important. Error strings no longer display provider internals.
4. **Network and code execution:** no `INTERNET` permission, external analytics calls, TLS certificate bypass, `Runtime.exec` / `ProcessBuilder`, WebView JavaScript bridges, or world-readable app files found in checked production Kotlin sources.
5. **Sensors and benchmarks:** listener unregisters upon screen disposal. CPU test is single-worker, limited to approximately two seconds, cancellable, and contains thermal cutoff. Microphone/camera/cross-app overlay tests are correctly marked unimplemented rather than simulated.
6. **Dependencies and CI:** pinned AGP 9.5.1, Kotlin 2.4.21 and Gradle 9.9.1; stable AndroidX BOM and coroutines as recorded in `DEPENDENCY-AUDIT-2026-11.md`. No dynamic dependency declarations in reviewed app Gradle file; Dependabot configured. Full transitive CVE and artifact provenance checks remain outstanding.
7. **Website:** static HTML/CSS/JS, no identified dynamic `innerHTML` assignment, `eval()` or external script injection. HTTPS GitHub links only, no backend/telemetry in site JavaScript.

## Dead-code review

- The reviewed source archive includes **39 production Kotlin source files** in `android/app/src/main`, plus tests, XML, Gradle and website sources.
- Lexical reference review of roughly **60 private declarations** found **zero single-occurrence private symbol candidates** in the previous release snapshot. Exported / navigation-invoked symbols are intentionally referenced through Compose route handlers; a symbol with two occurrences cannot safely be removed without runtime checks.
- **All 63/63** registered navigation destinations are enabled and have distinct concrete `AppRoot` dispatch handlers; no orphan `sections` labels, duplicated route IDs or missing dispatch branches were identified.
- Website CSS scan found **48 selector names**, all referenced in HTML or JavaScript. No unreferenced selector names were identified by the text-level check.
- Some features explicitly read “Not implemented” (camera/microphone, cross-app overlay and additional benchmarks). Those disclosures are **not dead code** and must not be deleted or replaced with fake results. Older release workflows remain as immutable history and should be archived separately, not deleted blindly.
- This is a structured lexical/route/resource audit, not a full control-flow proof or dynamic execution coverage. **Zero confirmed dead declarations** does not prove every branch is reachable under every device/permission state.
