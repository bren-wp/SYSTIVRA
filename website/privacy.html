Privacy information

Development preview — updated November 2026.

The current Android foundation is designed to inspect local device state without an account, advertising SDK, analytics SDK or mandatory backend. It uses Android system APIs to read available battery, memory, storage and sensor information.

Data collection

Core readings are processed on the device. Only after the user starts recording does SYSTIVRA save device metrics into a private SQLite database (up to 900 samples). These readings can be viewed after an app restart, separated into recording sessions, exported per session, or deleted individually after confirmation. A database migration retains records from the previous single-history schema. Android backup is disabled. Live measurements that are not recorded remain in memory. CSV and JSON exports both use a destination explicitly selected by the user, and report data is prepared and written away from the main application UI thread. JSON reports may include timestamps, battery, RAM, CPU load and thermal status but do not intentionally include device names or identifiers. No account creation or server-side telemetry is included.

Permissions

Core monitoring uses public Android APIs. ACCESS_NETWORK_STATE is used to inspect connection properties, but the app does not request INTERNET permission. Optional Usage Access is opened through Android system settings and is used only to display local app activity. Camera, microphone and cross-app overlay permissions are not requested in the current preview. Rejecting optional access does not block the dashboard.

Data sharing

Future report sharing must occur only after the user explicitly chooses it. External links (such as GitHub) are operated by their respective providers under their own privacy policies.

Contact & changes

For questions or corrections, open an issue at GitHub Issues. Review this policy again before a public production release; it describes the current source design, not a third-party privacy audit.
